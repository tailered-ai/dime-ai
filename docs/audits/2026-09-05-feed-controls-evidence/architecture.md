## Root cause and delivery path

The avoidable row space originates in layout. `client/src/pages/dimeModelFeed.css:173` defines a normal row grid: one column, two at a 622px league container, three at 940px; multi-column rows stretch. `client/src/components/projections/ProjectionCard.css:35` gives scheduled MLB cards an additional pregame region, while `:51` lets compact lifecycle cards align at the row start. Each row still reserves its tallest card's height, so shorter neighbors leave unused space. Internal content, name wrapping and card padding add height differences. Changing only `align-items` cannot shorten the shared row track. Compact, consistent card anatomy addresses the cause while retaining NCAAF kickoff order; masonry or status regrouping would change scanning order.

Full projections already use `ProjectionMarketsPopover` and the Radix portal in `client/src/components/ui/popover.tsx`. Opening that surface is not evidence of an inline expanding grid row. The parent must verify height stability after the card changes. This is a source-level diagnosis, not a before/after browser measurement.

`railway.json` selects the Dockerfile, one replica, `node dist/index.js`, and `/health`. `Dockerfile` builds with Node 22 and `pnpm run build`; `package.json:8` builds Vite client assets, checks production preview leakage, then bundles Express/tRPC with esbuild. `server/_core/vite.ts:93` serves the built client; hashed assets are immutable and HTML gets no-cache headers. These paths transport data and assets; none creates per-card spacer elements. There is no evidence supporting an infrastructure change for this symptom. A stale deployed asset remains a release-parity question for the parent, not a proven cause.

## Data, status and dates

`DimeModelFeed.tsx:1226` reads `games.list({sport:"NCAAF",gameDate})`, `games.list({sport:"MLB",gameDate})`, and `wc2026.matchesByDate({date})`. The calls poll every 60 seconds and retain previous-date placeholder data. Its combined order is NCAAF → WC → MLB (`:1213`); NCAAF sorts by Eastern kickoff across statuses (`:1298`). Filtering must preserve those arrays and identities.

`server/gamesListInput.ts:17` accepts optional sport/date and only upcoming/live/final as server status filters. `server/routers.ts:285` passes the dated query through `listGames`, validates team identities and applies presentation/publication/auth gates. `server/db.ts:252` keys its 60-second cache by sport/date, applies the exact requested date, retains NCAAF postponed/suspended rows, and excludes those statuses for other sports (`:312`). NCAAF also retains the existing book-line presence predicate. Thus client controls can truthfully filter returned statuses; they cannot expose MLB paused/postponed rows that the backend excludes. Adding server status filtering would incorrectly omit supported NCAAF states.

World Cup uses a separate exact-date SQL query with display-order/kickoff/id ordering (`server/wc2026/wc2026Router.ts:70`). It returns an ordinary match array, including an empty array when no match exists. The endpoint validates date shape, not the Gregorian calendar. The feed parser similarly accepts impossible days at baseline (`DimeModelFeed.tsx:185`). The new shared validator rejects those before querying. Date arithmetic uses UTC calendar fields, and “Today” uses `America/New_York` via `Intl`, including DST. This intentionally differs from `feedRoutes.ts:29`'s legacy effective-feed rollover; feed integration must pass `easternToday()` explicitly.

## Sources and helper contract

The dated NCAAF publication is bounded to source rows in `shared/ncaafSeptember5Sources.json` through `shared/ncaafSeptember5.ts` and `scripts/publishNcaafSeptember5.mts`. The publisher preserves existing lifecycle identity and reads provider statuses when required; its explicit mapping is scheduled → upcoming, inprogress/in_progress → live, complete → final, and delayed → suspended (`:402`). No new lifecycle inference is needed in navigation.

Conference ownership exists separately: `drizzle/cfb.schema.ts:17` defines `cfb_teams.conference`, seeded from `scripts/data/cfb-2026/teams.json`. `games.list` does not join that table. The small shared lookup is an exact projection of that repository's 138-team 2026 FBS snapshot; `manifest.json` dates its ESPN/FBSchedules provenance to 2026-07-25. Tests compare every affiliation and join feed ESPN identities to verify compatibility. The lookup does not ship the seed corpus. The 38 feed-registry opponents absent from that source remain unknown; no FCS conference or historical realignment is inferred. This is a 2026 snapshot, not season-aware metadata.

`feedNavigation.ts` keeps the PLAN interface: all-default filters; status/league/conference/game intersection; either participant may match a conference; unknown affiliations never match. League choices depend on status, conference choices on status+league, game choices on status+league+conference. Choices omit the control-owned All sentinel. Game selection uses exact ids, preserving doubleheaders; duplicate matchup labels append their actual ids because this interface supplies no start time or game number. The helper never sorts the feed or mutates source objects. `shiftFeedDate` throws `RangeError` for invalid dates, noninteger offsets or results outside 0001–9999.

## Integration and checks

The parent must validate route dates, use explicit ET today, preserve filter URL/back/forward state, clear stale game/conference/league choices only against settled current-date options, and prevent previous-date placeholders from appearing under the new date. Legacy sport-prefixed URLs should canonicalize without transiently restricting the combined query to NCAAF. Date arrows must respect the supported year bounds. Conference controls are empty for MLB/WC because this source only establishes NCAAF affiliation; codes from other sports must never collide with NCAAF team codes.
