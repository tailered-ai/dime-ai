### Mid-pass design change (r3 ledger entry): the 512-blockquote structural pre-cap

This change shipped inside the r2 pass without its own ledger entry —
it was a design decision made mid-pass while correcting MUT-01, not an
Appendix R item — so it reached the branch unreviewed. This entry,
its boundary fixtures, and the threat-model A8 reconciliation close
that gap (r3 evidence-closure).

- **What changed.** `parseBody` (`scripts/prx/body-check.mjs`) rejects
  any line whose leading run of `>` markers (spaces and tabs between
  markers included) exceeds `BLOCKQUOTE_DEPTH_CAP = 512`, by throwing
  BEFORE the CommonMark parser runs. `checkBody` degrades that throw to
  exactly one `PRX-B-SIZE` finding; `extractProse` degrades to `""`.
- **Why.** The MUT-01 correction proved the previous degrade was
  environment-dependent: `extractProse(">".repeat(20000))` overflowed
  the parser's recursion on one machine and parsed cleanly under
  Stryker's workers on another — catch-arm reachability varied with the
  runtime stack budget, so the SAME input produced different evidence
  in different environments. Blockquote nesting is the known recursion
  driver in the pinned parser, and the pre-cap makes that driver's
  degrade deterministic: the decision reads only the raw string.
- **What it replaced.** The environment-dependent parser-overflow
  degrade (catch wherever the parser happened to overflow). The catch
  remains as defense in depth for any other parser failure; it is no
  longer the primary bound for the known driver.
- **Cap value.** 512 is REPOSITORY_POLICY, not an external requirement:
  no sampled live PR body nests blockquotes beyond single digits, and
  the cap must sit far below every stack budget the checkers run under
  while leaving every legitimate document untouched.
- **Boundary fixtures (r3).** `PC511`/`PC512`/`PC513` pin the exact
  finding multisets at cap−1, at the cap, and at cap+1 (14×
  `PRX-B-SECTION-MISSING`, the same 14, and exactly one `PRX-B-SIZE`),
  each SHA-256-pinned in `adversarial-fixtures/manifest.json` and run
  by `adversarial-r2.test.ts`; `body-check.test.ts` carries the
  matching unit boundary test.
- **Residual risk, stated plainly.** (1) The pre-cap runs before
  parsing by design, so it has no fence context: a run of more than 512
  `>` characters inside legitimate fenced code content also degrades to
  `PRX-B-SIZE` — an over-approximation, pinned executable as `PCF600`
  so the behavior is visible rather than discovered; the author-side
  escape is shortening or splitting the quoted run. (2) The cap bounds
  only the leading-blockquote-marker shape; every other pathological
  parse shape remains bounded by the byte cap and the CI job timeout
  alone — threat-model A8's parse-cost residual is unchanged.
- **Claims-sync.** Register row 25 updated with the pre-cap enforcement
  point and the four fixtures.
