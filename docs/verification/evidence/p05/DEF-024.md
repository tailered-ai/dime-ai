# DEF-024 — P05.AUD01 false positives: signature hits treated as verdicts

**Severity:** MEDIUM (an unusable audit; it would have masked real violations
in noise, and a "known-noisy" audit is one nobody reads)
**Detected by:** P05.AUD01, first execution
**Affected:** `scripts/ci/selftest/p05-audit.mjs`

## DETECT

First run reported **22 LIVE_POISON_VIOLATIONs** and AUD01 FAIL. Every one was
legitimate pre-existing repository content: 18 real workflows referencing
`${{ secrets.* }}` (which every workflow must) and 4 historical migrations
containing `DROP TABLE`/`TRUNCATE`.

## ROOT CAUSE

The rule was "poison signature + gate-scanned root = violation". That answers
the wrong question. The audit's actual question is **did P05 introduce live
poison?** — not "does this repository contain those strings anywhere". This is
the DEF-009 class (raw matches are not a verdict), which the module's own
docstring warned about; I wrote the warning and then wrote the bug.

A second, quieter defect surfaced during the repair: the scan read only
`git ls-files`, so P05's own not-yet-committed fixture patches — precisely the
files whose inertness must be proven — were never examined. Adding them
exposed a third: `git status --porcelain` collapses a wholly-new directory to
one entry, so `--untracked-files=all` is required or the individual fixture
files stay invisible.

## CORRECT

Two independent, precise rules replace the blunt one:

1. **Marker rule** — every P05 poison carries `p05-poison`. That marker in a
   live executable/scannable file anywhere in the tree is a violation,
   whatever the path. This is the containment guarantee.
2. **Initiative rule** — a file *this initiative* added or modified under a
   gate-scanned root carrying any poison signature is a violation.

Everything else is CLASSIFIED, not cleared: `INERT_FIXTURE`, `TEST_CANARY`
(declared, each with a written reason), `DOCUMENTED_FINDING`, or
`LEGITIMATE_EXISTING_SOURCE`. Scan scope is now tracked ∪ initiative files,
with `--untracked-files=all`.

## RETEST

Post-fix: **0 violations**, 45 classified — 8 INERT_FIXTURE (all four fixture
directories, both files each), 1 TEST_CANARY, 4 DOCUMENTED_FINDING, 30
LEGITIMATE_EXISTING_SOURCE, across 4,289 files. AUD01 PASS.

## NEGATIVE RETEST

P05.NEG04 and the AUD01 negative case prove the audit can still FAIL: a live
poison file planted under a scanned root in a controlled temp tree is
detected, and the marker rule fires on a live scannable file carrying
`p05-poison`. The fix narrowed the rule without blinding it.

## CLOSE

Closed same-phase. Durable lesson: an audit that reports legitimate content as
violations is not "conservative", it is broken — precision is what makes a
gate readable, and the question the audit asks must match the property it
defends.
