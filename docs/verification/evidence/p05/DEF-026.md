# DEF-026 — an interrupted poison cycle stranded its candidate directory

**Severity:** LOW (gitignored scratch, no poison, no worktree registration, no
developer-tree mutation — but it violates the zero-residue requirement, and
the test that should have caught it did not look)
**Detected by:** the bounded residue check during the P05 regression sweep
**Affected:** `scripts/ci/selftest/assurance.mjs` (P05.T03), `P05.NEG07`

## DETECT

The post-regression residue check found five `worktree` directories under
`.ci-verify/runs/`. Two were pre-existing registered worktrees from earlier
sessions; **three were from this session** and were NOT registered git
worktrees. Each contained only `node_modules` — created inside the candidate
by the gate's own `npx` invocation. No poison, no tracked-file mutation.

The count matched the number of times `P05.NEG07` had run, which identified
the source immediately: the interrupted cycle.

## ROOT CAUSE

`runFixtureCycle` disposes its candidate in a `finally`, and the driver wires
P01's signal teardown. But the cycle also constructs a P04 `ExecutorRun`,
which wires **its own** SIGINT handler that calls `process.exit(130)` after
its teardown. Two independent handlers race: P04's exit can preempt P01's
removal partway, leaving the worktree unregistered (git removal ran) but the
run directory still on disk (`rmSync` never completed).

This is the same honest boundary P04 already documented for SIGKILL:
**in-process teardown is best-effort.** P05 inherited the boundary without
inheriting the recovery.

`P05.NEG07` asserted the things that matter most — no proof emitted, no poison
in the developer tree — but never asserted zero candidate residue, so a real
leak passed a green test.

## CORRECT

`sweepStaleRunDirs(runsRoot)` — next-invocation discovery, the same recovery
model P04 established. Ownership is proven **twice** before any removal:

1. the path must resolve inside the owned runs root (P04's
   `safeRemoveOwned` realpath containment), and
2. the directory must **not** be a registered git worktree — a live run from
   any session always is, so a concurrent run can never be swept away.

The sweep runs at the **start** of every assurance run, which makes zero
residue a standing property rather than a per-run hope: orphans cannot
accumulate across runs even when an interrupt preempts teardown.

`P05.NEG07` now asserts, after its interrupt, that the sweep leaves zero
orphaned candidates and that everything it skipped was skipped for the
registered-worktree reason.

## RETEST

Sweep run against the live tree: removed the 4 orphans (3 interrupt remnants
plus the DEF-022 spike remnant) and **skipped both pre-existing registered
worktrees with the reason recorded** — it did not touch another session's
work. Assurance run afterwards: `.ci-verify/runs/` contains exactly the 2
pre-existing registered worktrees. P05 suite 43/43.

## NEGATIVE RETEST

The protection is proven, not assumed: the two registered worktrees were
offered to the sweep and refused, each with `registered git worktree — live`.
A sweep that removed them would have destroyed unowned work — the exact
failure class P04.NEG07's ownership law exists to prevent.

## CLOSE

Closed same-phase. Durable lesson: when a phase inherits another phase's
best-effort boundary, it must also inherit that phase's **recovery**
mechanism — and a cleanup test that only checks the dangerous residue (poison)
while ignoring the boring residue (a directory) will report green on a leak.
