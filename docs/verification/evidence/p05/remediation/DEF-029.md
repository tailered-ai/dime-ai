# DEF-029 — origin/main advanced mid-session and now conflicts

**Severity:** HIGH · **Status: OPEN** · **Resolution owner: owner decision**
(bringing this branch up to date with the advanced main is a branch-integration
decision outside this authorization)

**Detected by:** P05.T03 — P01's snapshot machinery, which fetches
`origin/main` itself, returned `BLOCKED(MERGE_CONFLICT)` during the final
regression.

## What happened

`origin/main` moved during this session:

```
was:  4d644cf47d2ee8a1528e1efd8a79da5ce658d8c6
now:  1c17c5554a75be752307a686b7662fb6b10fb375
```

Five commits: PR #495 (deterministic global gstack bootstrap) and PR #480
(Dependabot bump of `pnpm/action-setup` 4.3.0 → 6.0.10). Together they touch
**18 workflow files**, including `ci.yml`, `01-pr-proof-contract.yml`, and
`08-contract-and-data-integrity.yml` — the three workflows hosting three of
the four gates P05 just proved.

`origin/main` is no longer an ancestor of this branch, and the prospective
merge does not construct:

```
CONFLICT (content): Merge conflict in .gitignore
```

Both sides independently added `.gstack/` to `.gitignore` — main via PR #495,
this branch back in the P01 commit, because running `browse` from the repo
appends it (documented in CLAUDE.md). Identical intent, textual conflict.

## Why this blocks P05 acceptance

1. **No candidate can be constructed.** Every P05 proof binds to a
   prospective merge. P01 correctly refuses to invent one, so the assurance
   suite cannot run at all — 8 P05 tests failed on exactly this.
2. **The existing proofs are now stale.** They certify a merge of
   *old main + this HEAD*. GitHub will evaluate *new main + this HEAD*.
   Certifying a revision GitHub will never evaluate is the precise failure
   this entire program exists to prevent — and P05's own NEG08 refuses a
   stale candidate binding by design.
3. **The frozen contract would drift.** The merged candidate would contain
   main's 18 changed workflows, so the contract regenerated against this
   branch no longer describes the merge, and seed-fixture step indices could
   shift.

## Why it was not resolved here

Merging `origin/main` into this branch would import 18 unreviewed workflow
changes plus a CI action bump, then require re-deriving the contract and
re-running every proof against the result. The authorization is explicit:
*"stop and report the blocker rather than expanding scope."*

The conflict itself is trivial — both sides want `.gstack/` ignored — but the
integration it is attached to is not.

## Recommended resolution (owner decision)

Authorize integrating `origin/main` into `feat/ci-verify-control-plane`
(merge or rebase), resolving `.gitignore` by keeping the single `.gstack/`
entry. Then, as a normal consequence, re-derive the frozen contract, re-run
the P05 assurance surface against the new candidate, and re-evaluate
acceptance. The `pnpm/action-setup` bump means the contract's action pins
change, which is expected and handled by the canonical regeneration path.
