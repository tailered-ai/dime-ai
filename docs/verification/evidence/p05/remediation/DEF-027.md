# DEF-027 — a pre-existing HIGH workflow-security finding blocks DEF-023 closure

**Severity:** HIGH · **Status: OPEN** · **Remediation owner: owner decision**
(the fix edits `.github/workflows/auto-merge-dependabot.yml`, an unrelated
workflow job that the DEF-023 authorization explicitly fences off)

**Detected by:** P05.T03, during the DEF-023 remediation preflight — before any
file was modified.

## The finding

```
error[bot-conditions]: spoofable bot actor check
  --> .github/workflows/auto-merge-dependabot.yml:27:9
   |
27 |     if: github.actor == 'dependabot[bot]' && github.event.pull_request.user.login == 'dependabot[bot]'
   |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ actor context may be spoofable
   = note: audit confidence → Medium
   = note: this finding has an auto-fix
```

`zizmor --min-severity high --format plain .github/workflows/` on the clean
repository exits **14**: `99 findings (47 ignored, 51 suppressed): 0
informational, 0 low, 0 medium, **1 high**`.

## Why it blocks DEF-023

DEF-023's fix makes `05-workflow-security` fail-closed. The gate scans the
whole `.github/workflows/` tree, so once it is honest it fails on this
pre-existing finding — on a **clean** tree, with no poison applied.

That was proven mechanically, not argued. Running the corrected gate through
the P05 ASSURANCE framework:

| Leg | Result |
| --- | --- |
| Poison (template injection applied) | **FAIL exit 14** — both declared detector signatures matched (`error[template-injection]`, `p05-poison-template-injection.yml`) |
| Control (poison reverted, byte-identical) | **FAIL exit 14** — this finding |
| Verdict | `BROKEN_GATE(CONTROL_RED)` |

So the corrected gate genuinely rejects, but cannot pass its control, and
therefore cannot become a PROVEN fourth gate. DEF-023's closure criterion
("rejects the known poison **and** passes its restored control") is
unsatisfiable while DEF-027 stands.

**Landing the DEF-023 fix without resolving this would turn the required
`05-workflow-security` check red on every pull request**, blocking all merges.
That is a worse outcome than the false-green it replaces, and it is not a
decision I may take.

## Why it is not fixed here

The DEF-023 authorization states: *"Do not alter: ... unrelated workflow
jobs"* and *"Do not ... broaden workflow-security scope."*
`auto-merge-dependabot.yml` is an unrelated workflow job. Editing it — even
by one line — is outside the authorized scope, and changing an auto-merge
guard condition is outward-facing behaviour.

Suppressing the finding (an inline `zizmor: ignore` or a config baseline) was
rejected outright: silencing a real finding to make a gate green is precisely
the failure mode this program exists to eliminate.

## Recommended remediation (owner decision)

The condition already contains the non-spoofable check
`github.event.pull_request.user.login == 'dependabot[bot]'`. The
`github.actor` clause is redundant, and it is the spoofable one. Dropping it
resolves the finding while strictly *strengthening* the guard — zizmor also
offers this as an auto-fix. One line, no behavioural loss.

Alternatives, if the owner prefers: use `github.triggering_actor`, or triage
the finding as accepted risk with a documented, reviewed suppression.
