# DEF-022 — wrong-cwd ledger invocation from a kept spike worktree

**Severity:** LOW (zero canonical-state corruption; the control plane's own
refusal surfaced it)
**Detected by:** the canonical writer's `EVIDENCE_MISSING` refusal during the
AMD-006 attempt

## DETECT

During P05 seed-gate feasibility spikes, the session shell `cd`'d into a
kept P01 spike worktree (`.ci-verify/runs/2026-08-10T11-21-46-589Z-18231-0/worktree`)
and the Bash tool's working directory PERSISTS between calls. Two subsequent
`ledger.mjs phase P05` invocations and one `amend` therefore executed the
WORKTREE'S copy of the scripts against the WORKTREE'S ledger copy. The amend
failed with `EVIDENCE_MISSING` (the worktree has no `evidence/p05/`), which
is what exposed the wrong cwd.

## ROOT CAUSE

`ledger.mjs` resolves its ledger path relative to its own module location
(correct, frozen behavior); the session violated its own invocation
discipline by leaving the persistent cwd inside a disposable candidate.

## BLAST RADIUS

Zero canonical corruption, verified: canonical ledger showed
`P05=NOT_STARTED`, `history=[]`, `amendments=5` before replay, and `verify`
reported only the EXPECTED pre-AMD blueprint drift. The two stray phase
transitions landed only in the worktree's disposable ledger copy, which was
disposed with the worktree.

## CORRECT

- cwd reset to the repository root; all subsequent ledger/gate commands run
  with the repo root as cwd (absolute-path discipline).
- AMD-006 + sync + phase transitions replayed against the canonical ledger;
  `verify` OK.
- The contaminated spike worktree removed via the P01-owned mechanism
  (`git worktree remove --force` + `prune`). The session's permission layer
  declined removal of the residual run-metadata directory (two inert JSON
  files, no working tree, no poison); it is classified as observational
  residue alongside the two pre-existing run directories.

## RETEST / NEGATIVE RETEST

- Canonical ledger `verify` exit 0 after replay; P05 progress 0/25 with the
  five AMD-006 units seeded exactly once.
- Negative: the P05 assurance runner being built in this phase NEVER changes
  the process cwd into a candidate — it passes the worktree exclusively as
  an explicit `cwd` to the P04 runner, so this class cannot recur inside the
  framework itself (asserted by the architectural-isolation audit's runner
  contract and the p05 suite, which runs everything from the repo root).

## CLOSE

Closed same-phase. The durable lesson mirrors the existing memory rule
"reproduce CI gates from the right cwd": the canonical writer's evidence
enforcement is ALSO a cwd tripwire — a refusal that names a path you believe
exists means you are not where you think you are.
