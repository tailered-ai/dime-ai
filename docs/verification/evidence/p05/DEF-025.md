# DEF-025 — P05 duplicated P01-owned ref resolution; P05.AUD02 exempted itself

**Severity:** MEDIUM (architectural duplication of a control-plane mechanism,
plus a hole in the audit meant to prevent exactly that)
**Detected by:** P01's provenance audit (`P01.NEG04`), during the first full
`scripts/` regression after P05 landed
**Affected:** `scripts/ci/selftest/p05-audit.mjs`

## DETECT

The full regression went from 587/587 to **3 failed / 630**, in three
prior-phase audits:

| Audit | Flag |
| --- | --- |
| P01 provenance (`P01.NEG04`) | `p05-audit.mjs:74` `remote-tracking-ref` — a real `git diff --name-only origin/main...HEAD` call |
| P01 provenance | `p05-audit.mjs:213,215` `rev-parse`, `commit-tree` — regex literals in the isolation table |
| P02.AUD01 / P03.AUD02 | `p05-audit.mjs` `yaml-parse-call`; `placement.mjs` `workflow-path` |

Two distinct classes, and they had to be separated before either could be
fixed — the whole point of the audits is that a red result is not
self-explanatory.

## ROOT CAUSE

**Genuine (one flag).** `initiativeFiles()` asked git for
`origin/main...HEAD` to compute which files this initiative touched. That
duplicates the base resolution P01's snapshot module owns — precisely the
mechanism `P05.AUD02` exists to forbid.

**Why my own audit missed it.** `auditArchitecturalIsolation` skipped the
*entire* `p05-audit.mjs` file on the grounds that a detector must name the
patterns it forbids. A per-file exemption also exempts every real violation in
that file — so the one module carrying the isolation law was the one module
exempt from it. P01's audit had no such blind spot and caught it.

**False positives (four flags).** Declaration-table text: regex literals
naming forbidden patterns, and `SENSITIVE_ROOTS` naming the workflows
directory it protects. Neither resolves a ref nor parses YAML.

## CORRECT

1. **Removed the ref resolution.** `initiativeFiles()` now uses working-tree
   state only (`git status --porcelain --untracked-files=all`) and resolves no
   refs. Containment does not depend on it: the marker rule scans every
   tracked file regardless of scope, and the initiative rule matters precisely
   while changes are uncommitted.
2. **Narrowed the exemption from per-file to per-ROW** (`isRuleDefinitionRow`),
   so the isolation law now applies to the audit module's executable code.
3. **Documented allowlist entries**, using the mechanism each prior audit
   already ships (file + written reason): `p05-audit.mjs` in the provenance
   ALLOWLIST, and `p05-audit.mjs` + `placement.mjs` in the P02/P03 YAML
   allowlists. No pattern was weakened and no other file's coverage changed.

I deliberately did **not** hide the strings (e.g. by moving them into JSON or
composing them at runtime) to dodge the scanners. Evading a detector to get
green is the failure mode this whole program exists to prevent; a reasoned
allowlist entry is the honest, auditable answer.

## RETEST

`scripts/` regression **630/630, exit 0** (36 files). P01 provenance PASS,
P02 yaml-audit PASS, P03 AUD01/AUD02 PASS, P05 AUD01 PASS (0 violations over
4,295 files), P05 AUD02 PASS (0 findings, all five required integrations
present).

## NEGATIVE RETEST

The narrowed exemption is proven to still bite: `P05.AUD02` finds violations
in the audit module's executable rows, and the P01 provenance audit still
fails on a planted ref-resolving call (`P01.NEG04`'s own negative fixture is
unchanged and still passes). The allowlist entries cover named files only —
every other module remains fully scanned.

## CLOSE

Closed same-phase. Durable lesson, and the sharpest of this phase: **a
detector must never exempt itself wholesale.** The exemption a detector needs
is for its *declarations*, not its *code* — and the difference is exactly
where a real violation will hide.
