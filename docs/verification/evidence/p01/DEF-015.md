# DEF-015 — false FAIL in the P01 sweep: prettier handed an unparseable path

| Field | Value |

| Severity | LOW |

## What happened
The sweep ran `npx prettier --check scripts/ci/ .gitignore` and recorded
`exit 2` with "Error occurred when checking code style in the above file."
Prettier has no parser for `.gitignore`, so passing it explicitly is an error —
the repository's formatting was never in question.

Opposite polarity to DEF-007 (false PASS): this is a false FAIL. Both are
evidence-accuracy defects. A checker that reports failures the repository does
not have is as corrosive as one that hides real ones.

## Root cause
An explicitly-passed path bypasses prettier's own ignore/inference rules.
`.gitignore` is covered by the repo-wide `prettier --check .` invocation, which
skips it by inference; naming it directly forces a parse attempt.

## Corrective action
Format-check only paths prettier can parse: `scripts/ci/`. `.gitignore`
correctness is instead asserted by the P01.T09 narrow-scope proof
(`git check-ignore -v` for each new pattern, plus a set of paths that must
remain visible).

## Retest

code style!". Sweep transcript regenerated.
