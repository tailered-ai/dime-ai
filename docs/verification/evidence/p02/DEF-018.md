# DEF-018 — required external tools silently under-detected (JSON-escaped matching)

| Field | Value |
| --- | --- |
| Detected by | P02.T04 (runnability review after the DEF-017 fix) |
| Severity | HIGH |
| Affected gate | P02.T04 / P02.T05 |
| Status | CLOSED |

## What happened
After DEF-017, `05-workflow-security` was reported `LOCAL` with no required
tools. It installs zizmor via `pipx install "zizmor==${ZIZMOR_VERSION}"`.
`03-semgrep-blocking` was likewise `LOCAL` despite installing semgrep.

## Root cause
`classifyStep` matched `TOOL_SIGNATURES` against `JSON.stringify(step)`. JSON
escaping turns `install "zizmor` into `install \"zizmor`, so the pattern
`/pipx install "?zizmor/` — which expects an optional quote immediately before
the name — no longer matched. Detection was being run against an escaped
rendering of the text rather than the text.

## Why HIGH
Under-reporting a required tool is worse than over-reporting it. A check marked
`LOCAL` with no tools tells P06 it can execute with the repository toolchain
alone. P06 would then run a gate whose binary is absent and either crash or —
far worse — treat the absence as nothing to do. The frozen rule is that a
missing tool must be `BLOCKED`, never green; this defect removed the very
signal that rule depends on.

## Correction
Match against the RAW step text: the `run` body and the `uses` reference,
concatenated unescaped. Escaped renderings are never used for detection.

## Retest
Re-emitted contract. `05-workflow-security` -> `LOCAL+TOOL` tools=[zizmor];
`03-semgrep-blocking` -> `LOCAL+TOOL` tools=[semgrep]. See
`raw/T04-runnability.txt`.
