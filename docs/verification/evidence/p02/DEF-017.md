# DEF-017 — check runnability conflated a CI-only SIDE-EFFECT step with a CI-only VERDICT

| Field | Value |
| --- | --- |
| Detected by | P02.T04 (first contract emission review) |
| Severity | HIGH |
| Affected gate | P02.T04 / P02.T05 |
| Status | CLOSED |

## What happened
The first emission classified `TypeScript Check`, `Vitest`, `Security Audit`,
`01-pr-proof-contract` and `05-workflow-security` as **CI-ONLY**. Those checks
are plainly reproducible locally — `tsc --noEmit`, `vitest`, `osv-scanner`,
`zizmor`.

Root cause: `classifyRunnability` marked the whole job CI-ONLY if ANY step used
an action in `CI_ONLY_ACTIONS`, and `actions/upload-artifact` is in that set.
Every one of those jobs uploads a report artifact, usually under `if: always()`.

## Why HIGH
Runnability is the field later phases use to decide what to execute. A check
wrongly marked CI-ONLY would be silently skipped forever by P06, and the local
verifier would claim parity while never running the repository's most important
gates. That is a false-green of exactly the class this control plane exists to
prevent — and it would have been invisible, because a skipped CI-ONLY check
looks intentional.

## Correct model
Runnability is a property of the steps that PRODUCE THE VERDICT, not of every
step in the job. Artifact storage is a side effect: removing it changes what is
uploaded, never whether the check passes.

Implemented as:
- Every step is classified individually (`LOCAL` / `LOCAL+TOOL` / `CI-ONLY`)
  and the per-step result is recorded in the contract.
- `NON_GATING_ACTIONS` (artifact upload/download only) marks steps as
  side-effect. They are REPRESENTED in the contract — never omitted — but do
  not drive the check verdict.
- Check runnability = worst case over GATING steps only.
- Job-level CI-ONLY causes (protected `environment:`, repository `secrets.*`)
  still make the whole check CI-ONLY, because those gate the job itself.

Nothing is dropped: `non_gating_step_count` and each step's own runnability are
emitted so the omission is auditable.

## Retest
Re-emitted contract; runnability re-derived. See `T04-runnability.txt`.
