# DEF-002 — live branch protection disagrees with the checked-in authority

| Field | Value |
| --- | --- |
| Detected by | P00.T02 |
| Severity | HIGH |
| Status | **OPEN — OWNER DECISION REQUIRED** |
| Affected gates | P02 (contract freeze target), P10.T04 (REMOTE reconciliation) |

## Root cause
`docs/verification/RULESETS.md` documents `main` as guarded by TWO independent
surfaces — repository ruleset 18701573 AND classic branch protection — with 4
pinned contexts, 1 required approval, code-owner review, last-push approval,
stale-approval dismissal, conversation resolution, and `enforce_admins`.

Live state, reproduced from six independent API probes with an `admin=true`
token (see `T02-required-contexts.md`):
- classic branch protection: **ABSENT** (404 "Branch not protected")
- org-level rulesets: **NONE**
- the only surface is ruleset 18701573, carrying **9** required contexts
- `required_approving_review_count: 0`, `require_code_owner_review: false`,
  `require_last_push_approval: false`, `dismiss_stale_reviews_on_push: false`,
  `required_review_thread_resolution: false`

## Explicitly NOT claimed
This is not characterised as a vulnerability. A 0-approval policy is plausibly
deliberate for a solo-maintainer repository, and the live ruleset is strict,
blocks force-push and deletion, and has zero bypass actors. The objective
problem is that the checked-in authority and the live configuration DISAGREE.

## Blast radius
1. **P02** freezes the merge contract against a target that has no agreed
   ground truth. Freezing now risks pinning the wrong authority.
2. **P10.T04** was designed to reconcile against "the live ruleset AND classic
   protection". One of those surfaces does not exist.
3. Any future reader of RULESETS.md is misinformed about live security posture.

## Corrective action — OWNER DECISION, outside this execution's authority
Exactly one of:
- **(A) Live state is correct** -> update `RULESETS.md` to describe the
  single-surface ruleset geometry and the 0-approval policy, and amend
  P10.T04 to reconcile one surface while asserting classic protection is
  deliberately absent.
- **(B) Documented state is correct** -> restore classic protection and the
  approval requirements. Repository-protection changes were explicitly placed
  outside this execution's authority and were NOT attempted.

## Regression test (after the decision)
P10.T04 must assert the chosen geometry and fail on divergence — including
asserting the ABSENCE of classic protection if (A) is chosen, so a silent
re-introduction is also caught.

## Retest result
Not yet retestable. Blocked on the owner decision.
