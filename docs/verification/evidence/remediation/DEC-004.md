## Why `yaml`, not `js-yaml`
1. **The pin would not have been exact.** `package.json` carries a pnpm
   override `"js-yaml": ">=4.3.1 <5.0.0"`, which applies to direct dependencies
   too — a range override defeats an exact pin. `yaml` has no override, so the
   specifier is authoritative.
2. **Zero new dependency surface.** `yaml@2.9.0` was already resolved
   transitively (vite's chain), so declaring it adds no package to the audited
   set. OSV and dependency-review verdicts therefore cannot change.
3. **Fit for P02's fail-closed contract.** eemeli/yaml is full YAML 1.2 and
   exposes `parseDocument` with explicit `errors`/`warnings` arrays and
   line/column ranges, which is what lets P02 abort on anything it does not
   understand instead of partially interpreting it.
