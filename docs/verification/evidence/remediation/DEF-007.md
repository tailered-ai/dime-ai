# DEF-007 — false PASS written into DEF-003 evidence by a piped exit code

| Field | Value |
| --- | --- |
| Detected by | P00.CP02 (review of the first DEF-003 validation transcript) |
| Severity | MEDIUM |
| Affected gate | DEF-003 corrective evidence |
| Status | CLOSED |

## Origin
A NEW failure created by remediation, so it takes its own ID.

## What happened
The first DEF-003 validation captured:

    pnpm install --frozen-lockfile 2>&1 | tail -4
    echo "FROZEN_INSTALL_EXIT=$?"

`$?` after a pipeline is the exit code of the LAST command (`tail`), not of
`pnpm`. The transcript recorded `FROZEN_INSTALL_EXIT=0` while `pnpm` had
actually exited 1. A false PASS was written into an evidence artifact — exactly
the failure class this control plane exists to prevent, and the same trap this
initiative flagged at the outset.

## Severity rationale
MEDIUM rather than LOW: the value was wrong in EVIDENCE, not merely in console
output. Had it gone unreviewed it would have been hashed into the ledger and
carried into the P10 execution-history binding.

## Root cause
Two faults:
1. Exit code read through a pipe.
2. The validation conflated "the lockfile is in sync" with "the whole install
   succeeds", so a pre-existing environment failure masqueraded as the claim.

## Corrective action
1. Every exit code in the regenerated transcript is captured DIRECTLY:
   `cmd > file 2>&1; EXIT=$?` — no pipes.
2. The lockfile claim is isolated with `--ignore-scripts`, and the unrelated
   failure is diagnosed explicitly rather than hidden.

## What the real result is
- `pnpm install --frozen-lockfile` -> exit **1**, from the repo's pre-existing
  `postinstall` (`pip3` -> PEP 668 `externally-managed-environment` on this
  macOS host). pnpm still reports `Lockfile is up to date, resolution step is
  skipped`. The postinstall script is unchanged by this branch (0 postinstall
  lines in the `package.json` diff), so this is pre-existing local-environment
  behaviour, not a regression. CI runs on `ubuntu-latest`, where the same
  script installs normally.
- `pnpm install --frozen-lockfile --ignore-scripts` -> exit **0**, lockfile
  byte-identical afterwards. This is the determinism claim, proven cleanly.

## Retest
Regenerated `DEF-003-validation.txt` with direct exit capture. Sections D/E now
report exit 1 (with diagnosis) and exit 0 (isolated) truthfully.
