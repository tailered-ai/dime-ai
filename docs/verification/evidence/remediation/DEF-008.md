# DEF-008 — negative proof passed for the wrong reason

| Field | Value |
| --- | --- |
| Detected by | P00.CP02 (review of the first CP02 sweep transcript) |
| Severity | LOW |
| Affected gate | P00.CP02 corrective evidence |
| Status | CLOSED |

## Origin
A NEW failure created by remediation, so it takes its own ID.

## What happened
The first CP02 sweep proved self-reference refusal with:

    ledger.mjs set P00.CP02 PASS --evidence docs/verification/ci-verify-ledger.json

It exited 1 and was recorded as a passing negative. But `setStatus` checks the
state machine BEFORE it validates evidence, so `P00.CP02` (then `NOT_STARTED`)
tripped `ILLEGAL_TRANSITION` and the evidence path was never reached. The line
proved the transition guard, not `EVIDENCE_SELF_REFERENCE`.

## Why this matters
This is precisely the `expected_gate` / `expected_reason` discipline the
blueprint mandates for P05: a fixture must fail for its DECLARED reason, not
merely turn something red. A red exit attributed to the wrong cause is a
false proof, and the three sibling detectors in the same sweep were only
verified by exit code.

## Corrective action
1. The self-reference negative now asserts against `collectEvidence()`
   directly — the real code path, with no state machine in front of it.
2. EVERY negative in the sweep now prints the matched reason token, so an exit
   code alone can no longer stand in for a proof.

## Retest
Regenerated sweep:

    tampered JSON              -> exit 1  reason: LEDGER_TAMPERED
    tampered markdown          -> exit 1  reason: RENDER_DRIFT
    mutated evidence artifact  -> exit 1  reason: STALE_EVIDENCE
    self-referential evidence  -> exit 1  reason: EVIDENCE_SELF_REFERENCE
    restored                   -> exit 0  VERIFY OK

## Note
`ILLEGAL_TRANSITION` firing before evidence validation is CORRECT behaviour and
was not changed. Only the proof was wrong.
