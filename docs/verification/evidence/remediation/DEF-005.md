# DEF-005 — GEN-000 recorded `git_head_at_bootstrap: "unknown"`

| Field | Value |
| --- | --- |
| Detected by | P00.CP02 (re-evaluation baseline read) |
| Severity | MEDIUM |
| Affected gate | PB.T03 (genesis record) |
| Status | CLOSED |

## Root cause
`parseArgs` treated EVERY `--flag` as taking a value. The bootstrap command
was:

    node scripts/ci/ledger.mjs init --force --head "$(git rev-parse HEAD)"

so `--force` consumed the literal token `--head` as its value, the real SHA
became a stray positional, and `cmdInit` fell through to its
`flags.head ?? "unknown"` default. Because `"unknown"` is truthy, the
presence-only `GENESIS_INCOMPLETE` check accepted it.

Two independent faults, both fixed:
1. **Parser** — `BOOLEAN_FLAGS` (`force`, `flaky`, `no-flaky`) now take no
   value, so a boolean flag can never swallow the next token.
2. **Validation** — `verify` now requires `git_head_at_bootstrap` to match
   `/^[0-9a-f]{40}$/`. A placeholder can never satisfy it again.

## Blast radius
GEN-000 is bound into the P10 execution-history hash, so the trust root would
have carried a placeholder instead of the real bootstrap commit. No status,
evidence hash, or decision was affected — only the provenance field.

## Corrective action
GEN-000 is NOT rewritten. The correction is recorded append-only in the
amendment log as a `genesis_corrections` entry carrying both the superseded
value (`unknown`) and the corrected value, so the original error stays
visible. `resolvedGenesis()` applies corrections in order; `verify` validates
the RESOLVED value.

Corrected value: `4d644cf47d2ee8a1528e1efd8a79da5ce658d8c6` (branch `feat/ci-verify-control-plane`,
cut from `origin/main` at the same SHA; the branch has no commits yet, so
bootstrap HEAD and base are identical).

## Regression test
`PB.NEG03` includes a parser case asserting `--force --head <sha>` yields
`flags.force === true` and `flags.head === "<sha>"`, plus a genesis case
asserting a non-40-hex `git_head_at_bootstrap` is rejected.
