# DEF-001 — self-referential evidence is structurally invalid

| Field | Value |
| --- | --- |
| Detected by | PB.T02 (design inspection while choosing PB.T02's evidence path) |
| Detected how | INSPECTION, before it manifested as a failing run — stated precisely, not as a caught runtime failure |
| Severity | LOW |
| Affected gate | PB.GATE01 |
| Status | CLOSED |

## Root cause
`ci-verify-ledger.json`, `ci-verify-ledger.sha256`, and
`CI-VERIFY-EXECUTION-LEDGER.md` are rewritten on EVERY ledger write. Recording
any of them as a unit's `evidence` captures a hash that is stale the instant
the next unit is recorded, so `verify` would report STALE_EVIDENCE permanently
and the ledger could never reach a clean state.

## Blast radius
Would have affected PB.T02, PB.T04, PB.T05 immediately, and every future phase
whose deliverable is a live control-plane artifact. Left unfixed it would have
made `verify` permanently red, which trains an operator to ignore the audit —
the precise failure mode this control plane exists to prevent.

## Corrective action
1. Convention: evidence artifacts are IMMUTABLE observation records under
   `docs/verification/evidence/`; live artifacts are cited BY HASH inside such
   a record, never used as an evidence path.
2. Mechanism: `collectEvidence()` now refuses the three live control-plane
   paths with `EVIDENCE_SELF_REFERENCE`. Enforced at write time, not merely
   documented.

## Regression test
`scripts/ci/ledger.test.ts` -> "refuses evidence pointing at a live
control-plane artifact (DEF-001)" — asserts all three paths throw.

## Retest result
- Targeted: regression test PASS.
- Relevant regression: full PB suite 20/20 PASS (`PB-validation-run.txt`).
- Negative retest: `PB-GATE01-negative-proof.txt` CASE 4 shows a live CLI
  attempt refused with exit 1.
- Ledger reseeded (`init --force`) before any status was recorded, so no unit
  ever carried invalid evidence.

## Note on history
Correcting this changed `scripts/ci/ledger.mjs`, which changed
`ledger_impl_sha256`. Because the correction landed BEFORE any unit status was
recorded, genesis GEN-000 was re-seeded rather than superseded. Any equivalent
change after recording would instead surface as LEDGER_IMPL_DRIFT and require a
new defect ID.
